# 真实写入后端（0.2.6 预发布版）

面向 Raspberry Pi OS Trixie ARM64。GTK3 进程使用普通用户权限，点击“写入”后自动检查缓存；缺少文件时从本仓库统一固件目录下载固定哈希镜像（来源仍指向上游固定提交），通过大小、SHA-256 和镜像结构检查后，经一次 Polkit 管理员授权进入维护事务。

所有通过发布公钥验签的目录条目均可发起写入，包括当前四个官方版本与 DIY 0.4.1 / 0.3.0 / 0.2.0。`hardware_verified` 仅说明硬件验收状态，不禁用写入。未经签名的 JSON 或任意本地 bin 不能获得提权写入授权。

## 设备与授权

`/etc/typix-copilot/board.json` 是管理员维护的板载连接配置。随包配置对应 0720 板，控制器 `fe9c0000.xhci`、内部 Hub `1a40:0201`、端口 `1-1.2`。每次运行都检查 sysfs 枚举关系、产品模式、唯一直属 CDC 端口及打开后设备号；不同 CM 或 USB 拓扑必须重新验证配置，不能仅改型号名称或使用第一个 ttyACM。

2026-09-15 对另一台 CM0 的被动检查发现：同一内部 Hub/port2 位于 `3f980000.usb` 控制器下，运行态产品为 `TypixDeck UAC+CDC`，且只有一个直属 CDC 接口。若该设备保留随包的 CM4 `fe9c0000.xhci` 配置，程序会正确拒绝并显示“设备和板载配置不一致”。该实物已在取得写入互斥锁、确认没有维护会话、备份原配置后改为绑定实测路径；普通用户复查可识别运行态。本次只修正系统配置，没有打开串口、进入 ROM 或刷写固件。

[CM0 配置示例](../packaging/boards/typixdeck-0720-cm0.json) 供管理员核对实物后部署。选择依据是运行时的控制器、内部 Hub、物理端口、产品与唯一直属接口，不能仅凭型号应用此文件。随包默认仍对应先前 CM4 的精确连接；未知拓扑继续拒绝写入。设备上的 `/etc/typix-copilot/board.json` 是 Debian conffile，升级时应保留已核对的本机配置。匹配通过不代表电源保持、恢复或完整刷写链路已经验收。

固定 helper `/usr/libexec/typix-copilot-write` 只接收所选固件 ID，以及 stdin 中有界的签名目录封装与随后的镜像内容。封装固定为 8 字节 magic、4 字节大端 JSON 长度、64 字节 Ed25519 签名和原始 JSON（最大 256 KiB）；root 在接触板载设备前用安装目录中的公钥重新验签，绑定所选 ID、版本、大小和 SHA-256。它不接收文件路径、脚本、串口、地址或 esptool 参数；以隔离 Python 启动，使用 root 安装的公钥、板配置和固定 esptool 5.3.1。授权不在 GUI 中保存，也不设置免密常驻 root 服务。

## 真实事务

1. 全局锁、存储空间、固件大小/哈希/结构检查；未知目标或繁忙端口拒绝操作。
2. 已绑定正常固件的 CDC 连接仅发送 `AW_DUMP`，提取 CONFIG_P0 的电源/复位输入状态；其余原始串口数据丢弃。此状态不是物理供电连续性的保证。
3. 发送固定官方维护命令，等待相同板载端口进入 ROM；运行态 CDC 需要 DTR 连接标志，ROM 不使用通用 DTR/RTS 复位。
4. 在 ROM 中验证 chip ID 9、安全启动/加密/下载配置与 Flash 容量；受保护或无法验证的状态停止。
5. 读取整个 8/16 MiB Flash，校验传输、落盘、重新读取文件核对，保存本机私有备份。备份完成前不会擦除或写入 Flash。
6. 历史镜像保持偏移 `0x000000` 完整写入语义，会覆盖 NVS。v2 目录可明确授予 `preserve-diy-v1`：核对设备完整分区表扇区与目标一致、NVS 类型/边界/未加密标志一致、目标设置区全为空白，且设备完整 app 摘要在签名兼容列表内，然后仅将备份的 NVS `0x9000..0xF000` 覆入私有有效镜像。任何不符都在擦写前停止，绝不静默重置设置。固定 `keep` 参数，不执行 erase-all，不自动断线重连重试。
7. 重新读回整个写入范围，逐字节与有效预期内容比较，包含保留的 NVS；不只依赖工具的写后 MD5。签名原始镜像及公开哈希保持原样，有效镜像包含私有设置，只存本机 0600 文件，不公开其内容或摘要。
8. 清除且读回确认 FORCE_DOWNLOAD_BOOT 位，再发 ESP32 watchdog reset；等待同一端口恢复正常 USB 固件枚举。

旧官方固件没有可信运行版本握手。即使全部完成，准确结果也是“写入已校验，设备已重新连接；运行版本待确认”，不把 USB 枚举等同于版本证明。

维护前仅暂停 Polkit 调用用户原本运行的 `typix-companion-cdc.service`，通过固定 systemctl 参数以该用户身份调用其用户管理器；不存在或未运行的服务不会启动。关闭串口后仅在相同板载配置探测到正常固件枚举时恢复。若设备仍在 ROM、连接丢失或恢复失败，记录“串口服务待设备恢复后重启”。配置不兼容的拒绝也可能已进入维护模式，界面明确提示需要恢复；本版不添加自动复位或电源切换。

第二版目录独立使用 `firmware/index-v2.json` 与相邻签名，防止旧版写入器忽略保留策略而清空 NVS。历史 `index.json` 及其字节保持原样，旧客户端继续看到原有条目；新客户端仍可验证旧签名缓存凭据。

## 本地数据与中断

- 普通用户缓存：`~/.cache/typix-copilot/artifacts/<sha256>.bin`，每次复用重新校验。相邻 `<sha256>.<元数据摘要>.proof` 按准确版本保存原始签名目录，支持从在线目录移除后的旧版本。兼容旧 `<sha256>.proof`；「本地固件」移除所选版本凭据，仅在没有其他有效版本共用该文件时删除 bin，不删除备份或记录。
- 公开给本机 GUI 的最小结果：`/var/lib/typix-copilot/status.json`；仅保留最近 20 个任务的固件 ID、版本、镜像 SHA-256/大小、阶段、布尔结果和随机任务编号，没有芯片唯一标识或原始串口内容。
- 本机详细日志：`/var/lib/typix-copilot/logs/<随机任务号>.json`，目录 0755、文件 0644，随历史保留最近 20 个任务。每份最多 192 个阶段/整数进度事件、128 KiB，达到上限时保留首条与最终状态并标记省略。记录阶段相对耗时、读取字节数、失败地址、固定异常类别及脱敏模块/函数/行号；不保存原始异常消息、设备唯一标识、串口流、Flash 内容或本机路径。GUI 按准确任务与固件身份检查文件、权限和上限，展开后读取，用户可主动复制。旧版本没有阶段文件时只展示原摘要。
- 私有备份及审计：`/var/lib/typix-copilot/private/<随机任务号>/`，目录 0700、文件 0600。Flash 备份可能包含设置，禁止上传到 GitHub 或复制进公开发布材料。
- 独立的私有维护状态记录与显示历史分离，后续失败请求不会抹掉尚未结束的 ROM 会话。允许重新明确授权、向同一板载连接写入签名目录镜像；不自动反复刷写。

下载阶段可取消；授权开始后锁住页面导航及正常退出，不向写入 helper 发送取消信号。GUI 意外消失后 helper 忽略常规挂断信号并继续已开始事务，进度管道采用有界非阻塞写入；重新打开界面读取本机结果。操作系统强杀、掉电或内核故障无法由 GUI 阻止，残留进行中状态不能自动视为成功。写入开始后的进度日志落盘失败也不打断 Flash 协议，结果标记记录保存不完整。

失败时保留缓存和已有备份，不声称自动回滚。尤其“尚未开始写入”也可能已经进入 ROM。Linux 重启不保证让 ESP32/AW 掉电或恢复；若维护 USB 仍能连接，可重新授权写入。若 USB 不再可达，可能必须拆机接触 BOOT/RESET 或使用已核对的外部维护连接；不通过猜测 GPIO/I2C/屏幕 MUX 恢复。

## 构建与验证

```sh
python3 tools/build-deb.py
PYTHONPATH=src python3 -m unittest discover -s tests -v
python3 tools/check-live-gtk.py
```

构建器下载并校验固定 esptool 5.3.1 源码归档（SHA256 `125781f36e6a2d08c484524a45f340694675368b5eeead9d0cb21b2034a91d98`），只打包 Python 包、必要 stub 与许可证；其余依赖使用 Debian 包。系统已有 esptool 不被覆盖。`.deb` 声明架构、Trixie 兼容性和依赖，`build/payload-manifest.json` 可核对安装内容。

0.2.2 候选只将 ESP32-S3 generation-2 RAM stub 替换为官方 v1.2.2（与 esptool v5.4.0 所带资产完全一致），保留已审查的 5.3.1 主机协议代码和依赖。构建时独立核对 stub 的 SHA256 与长度。它包含 USB 帧满 64 字节时发送结束包的上游修复；固定来源、许可证和硬件验收限制见 [vendor/README.md](../vendor/README.md)。该维护程序纳入 0.2.4 预发布版；CM4 完整备份/写入/回读仍待验收。

单元/GTK 测试使用明确的替身，不触碰硬件；真机结果另行记录，不能从测试通过推断已刷写。

## 旧协议兼容与硬件验收状态

旧协议缺少 AW_DUMP 时，普通界面拒绝未验证的供电状态。写入器保留受限的首次升级许可机制供人工审查后的实验使用，GUI 与软件包不会生成此许可。许可由管理员维护，绑定板配置、目标固件、认证用户和单次启动，在五分钟内有效且只消费一次；不能因 AUDIO_DUMP 正常就宣称供电安全。维护恢复也不能自动复用已消费的许可。

2026-09-14 的 CM4 测试中，官方 2026-09-10 镜像完成实际写入并保存完整私有备份，但独立读回校验中断。随后整机重启恢复了两侧显示，不能用显示恢复代替校验成功。0.1.3 后续测试又在备份读取期间通信失败，尚未开始擦写；64 KiB 分段没有解决问题。

0.1.4 保留严格的失败状态和固定类型诊断，不把未知结果显示为成功。在线目录和下载功能仅在本机以替身及真实公开文件验证，未恢复硬件维护测试。完整刷写链路尚未验收，请暂停重复刷写；恢复操作必须基于实际设备状态另行检查。

0.2.0 移除单一官方版本白名单，统一在线和本地缓存写入。软件测试覆盖六个真实发布镜像与替身硬件事务，未在本轮重新连接串口或刷写；既有通信故障仍待单独真机验证。目录签名与包内离线副本由 `tools/sign-firmware-index.py` 同步生成。

0.2.1 增加详细写入记录与只在内存更新的块内计数：已接收字节、距离最后数据包时间、是否在等待摘要。日志落盘仍在整块读取和摘要校验结束后执行，不改变读取分块、重试、擦写或复位策略。GUI 准备/下载阶段的失败保留会话摘要；持久阶段计时从系统 helper 开始。

本轮检查到一次 DIY 0.3.0 尝试同样在备份 `0x000E0000` 中断，未开始擦写。随后一次有锁且绑定原会话的有限诊断只尝试同步已有 stub，在同步阶段串口异常，未进入计划的读取，未发送擦写或复位命令；被动复查 SSH 与 ROM USB 可见。此结果不能证明该 Flash 地址有缺陷，也不构成通信修复或刷写验收。

随后读取到另一条已保存的 DIY 记录，失败阶段为进入维护模式（`rom-timeout`），同样未开始写入。新界面按任务编号分别呈现，不能把不同阶段的失败合并成同一原因。


0.2.3 候选进一步保留运行态 CDC 连接直到相同端口进入 ROM，超时关闭但不重发维护命令；`flush()` 只代表主机提交完成，固件在 1 Hz 任务中才执行维护请求。ROM 同步若检测到已存在 RAM stub，则拒绝直接复用，因为旧版本可能仍驻留在内存中。以上行为已通过软件回归测试，进入维护模式稳定性仍须真机复测。

2026-09-29（本地时间）已通过签名 Store staging 安装 0.2.2 候选并核对所有安装文件。用户随后一次请求在进入维护阶段超时；只读 AW 查询无回复。一次绑定单个 ESP USB 设备的人工恢复操作后出现 ROM 枚举，但同步无回复，尚未加载新 stub，也未执行任何 Flash 擦写。当前需整机重新启动后继续完整备份/回读验收；未将实验性 USB 恢复加入普通写入流程。

0.2.4 发布上述维护改进，收录固定源码提交的 DIY 0.4.1 镜像，更新签名在线及离线目录。没有取消备份、板级检查或独立回读；未通过端到端验收的状态保持不变。

## 0.2.5 下载与代理修正

此前下载、TLS/超时、缓存 I/O 与内容校验的不同异常，在进入 UI 时全部丢失为 `cache_failed`。现在使用固定错误类别，HTTP 状态只保留 100–599 的整数，详细记录标明准备阶段；不保存 URL、响应正文、异常原文、代理凭据或路径。仍保持签名、大小、SHA-256、镜像结构检查及下载前可取消行为。旧日志无法恢复当时没有保存的错误原因。

本地 182 项测试通过，包含 DIY 0.4.1 发布文件的完整缓存与签名凭据回归、网络/存储错误的 UI/日志传播、失败时不启动写入器，以及使用代理/NO_PROXY 时仍验证 HTTPS 源站证书。传输遵循桌面 `HTTP_PROXY` / `HTTPS_PROXY` / `NO_PROXY`（兼容小写）；不自动填写代理地址，不记录代理凭据，未配置时直连。签名、固定来源、拒绝重定向和完整性校验继续生效。

2026-09-30 在 CM4 复现域名解析失败，旧客户端将错误折叠为“固件下载或文件校验失败”。当时 FlClash TUN 的 DNS 返回 SERVFAIL，本地代理也无法建立 TLS；重启原生客户端后恢复解析和下载。旧 Copilot 同时忽略桌面已配置的代理，本版修正这一点。本次没有更改 FlClash 订阅、节点或 DNS 配置，也没有证明以后重启不会再发生该网络故障。

CM4 从 0.2.3-1 升级到 0.2.5-1，安装包经签名 Store staging、限定单包 apt 安装及完整 payload 核对，板级配置保持原样。使用安装后的代码重新获取七版本签名目录，从空缓存下载 DIY 0.4.1（3,997,320 字节，SHA256 `c72336499a47a8316bc02594e4de9dd46052c2099df2ef796e353d7e7de99903`），校验签名凭据并通过无网络缓存复用。本次未打开串口或进入维护模式，系统刷写记录未变；这些结果只验收下载路径。
