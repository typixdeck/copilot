# 固件项目、版本与编译产物接入

Copilot 是 TypixDeck 板载 ESP32-S3 协处理器的 Firmware Store。它接收固件项目已经编译好的文件，在树莓派主系统上管理版本、下载、缓存与写入。0.1.4 已实现本仓库 JSON 在线目录、bin 下载、离线缓存及本地镜像检查。实际发布格式见 [firmware 目录](../firmware/README.md)。本文其余 Release 枚举、ESP-IDF 构建目录和 `.tpfw` 接入仍是后续设计。

## 管理对象

| 对象 | 内容 |
| --- | --- |
| 固件项目 | 名称、功能、作者、原项目链接、截图及适用的 TypixDeck 板级配置 |
| 版本 | 发布说明、显示版本、产物修订、可用文件与设置影响 |
| 产物 | 原始来源、固定文件位置、实际大小/hash、完整镜像或分段类型、写入描述 |
| 本机状态 | 已下载、校验结果、上次写入、经握手确认的运行身份、恢复版本 |

官方、自研和第三方是来源分类，不是三套写入器。一个项目可有多个版本；相同显示版本若出现不同字节，必须形成新的产物修订并重新审核，不能替换已缓存版本。下载完成不代表已写入，写入记录也不代表已确认当前运行身份。

## 输入规划与实现状态

| 输入 | 接入方式 | 写入前需要补齐的内容 |
| --- | --- | --- |
| GitHub Release 资产 | 枚举所选项目的发布版本和文件；选中后固定资产标识与预期 hash | 板级适配、镜像类型、布局及数据影响；同名资产更换时拒绝沿用旧审核 |
| GitHub 仓库文件 | 源配置声明产物目录/文件；分支只用于发现，下载时解析到完整 commit 与固定路径 | 逐产物映射，不能从 `.bin` 扩展名或目录名推断写入地址 |
| 本地合并 `.bin` | 保留原文件字节，复制到内容寻址的本机库并解析镜像/分区 | 对应项目、适用板级配置、已审核完整镜像写入描述 |
| 本地 ESP-IDF 构建输出 | 读取 `flasher_args.json` 的文件偏移映射与允许的 Flash 设置，收集实际引用的文件 | 构建来源、板级适配和更新方式；所有设置均与文件及设备检查结果交叉核对 |
| `.tpfw` 离线包 | 导入可选的清单、签名、文件与说明集合 | 与其他输入相同的校验要求 |

ESP-IDF 5.4.2 的 [官方模板](https://github.com/espressif/esp-idf/blob/v5.4.2/components/esptool_py/flasher_args.json.in) 定义了 `flash_files`、`flash_settings` 和工具参数等字段。Copilot 只提取白名单内的数据；不直接执行参数数组，不接受任意命令、复位策略或 hook。路径必须局限在选定的产物根目录，拒绝外部绝对路径、穿越、符号链接和缺失文件。构建输出引用根目录外的字体等资源时，应由发布方把所需文件整理到同一产物目录，再更新相对路径清单。

合并镜像和应用镜像分别识别：应用 `.bin` 不得自动作为完整镜像从 `0x0` 写入。无法从可信描述及实际文件确定用途的产物可以先收藏，补齐信息后再成为可写版本。

上述 commit 是发布文件所在提交，不构成编译源码的可重复构建证明；文件名日期仅能作为显示线索。上游具体写入依据见 [固定刷写脚本](https://github.com/TypixNode/TypixDeck-esp32s3-firmware/blob/fde9dac3b687a92fa2a6a049b5cd953dcb367b23/release/flash_esp32.sh)。

Copilot 对该项目维护一份经过审核的产物接入描述，从本仓库统一固件目录下载与原项目逐字节一致的镜像，保留原项目的固定来源链接，不要求上游先提供新容器格式。不同历史镜像分别解析布局和设置影响；不会给整个项目的所有 `.bin` 套一个通用偏移。上游脚本仅作为实现依据，不作为下载后执行的程序。

## 固件商店中的快速切换

1. 选择项目与版本，下载到本地库；已经下载且校验一致时直接复用。
2. 核对当前 TypixDeck 的板载目标、产物兼容性和本地恢复版本，展示设置及功能变化。
3. 用户确认并完成系统授权后，短命 helper 对固定副本和同一板载设备执行写入、校验、复位及重枚举检查。
4. 保存脱敏结果；切回时选择缓存中的先前版本，执行同样的写入流程。

当前官方布局为单 `factory` 应用，因此快速切换通过重新写入实现。缓存减少重复下载，已审核接入描述减少重复配置，不承诺切换为零耗时或无需实际写入。

来源发现、文件下载和数据解析默认以普通用户身份运行；浏览、刷新和导入不触发串口操作。一个已校验的内置板级描述负责识别 TypixDeck 内部协处理器连接，不能将外接 ESP32 或任意 `/dev/ttyACM*` 自动纳入目标。对应设备身份和当前状态仍由每次维护事务重新检查。

网络失败可保留已校验的离线版本；缓存缺文件、空间不足、源文件变化、产物元数据冲突或板载目标不明确时，保留用户原有收藏，展示具体原因并允许修复后重试。写入阶段的取消和中断恢复遵循 [产品事务设计](PRODUCT.md)。
