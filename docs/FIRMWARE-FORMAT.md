# 固件包协议草案

本文件是后续扩展包格式的设计草案，`.tpfw` 尚未实现。0.1.4 现行 JSON 索引与合并 bin 格式见 [firmware 发布约定](../firmware/README.md)，现有写入器的范围见 [真实写入说明](REAL-WRITER.md)。目标是 TypixDeck 板载 ESP32-S3 协处理器。固件商店同时接收官方、自研和第三方项目的编译产物；统一内部描述用于校验、版本管理和生成可审查写入计划。

## 一个固件版本包含什么

接入时支持原始 `.bin`、ESP-IDF 构建输出和 GitHub 发布资产；由发布者清单或已审核的源适配描述生成 `firmware.json`，保留原始二进制字节。受限 ZIP bundle（暂称 `.tpfw`）是可选的离线打包形式，可携带清单、发布者签名、分段、许可证和说明。线上与离线最终采用相同的文件、布局、板级与信任校验，具体映射见 [固件来源与产物](ARTIFACT-SOURCES.md)。

| manifest 字段 | 要求 |
| --- | --- |
| `schemaVersion`、`id`、`version`、`revision`、`name` | 稳定固件项目身份与不可变版本/产物修订；同版本换字节需新修订 |
| `publisher`、`license`、`source` | 作者/发布者、许可证、仓库与准确 commit 或可追溯构建来源 |
| `target` | `typixdeck-onboard-coprocessor`、`esp32s3`、已验证 TypixDeck 板级配置标识、Flash/PSRAM 容量、模式/时钟及安全状态要求；不包含设备序列号 |
| `layout` | 分区布局ID、布局摘要、受支持的当前布局及设置格式版本 |
| `installMode` | `app-update` 或 `layout-replacement`；第一版没有 `ota-switch` |
| `segments[]` | 相对文件路径、用途、数值偏移、实际大小和 SHA-256；禁止重叠/越界 |
| `capabilities` | 电源保持/关机链、MUX、显示、触摸、UAC、CDC维护与恢复协议的明确支持状态 |
| `settings` | NVS/字体兼容声明与重置需求；最终影响还须由实际范围计算核对 |
| `recovery` | 已审核恢复固件的ID/版本/hash、适用前提和人工恢复说明 |
| `verification` | 启动后如何确认固件身份、协议版本和能力；不运行第三方任意命令 |

所有字段都不具有执行权限。不能声明命令行、shell hooks、下载后执行脚本、GPIO寄存器写入或自定义提权程序。

## 固定文件校验规则

- 解包拒绝绝对路径、`..`、重复名称、符号链接、设备文件和超额文件/大小；先检查空间，失败不替换已有收藏。
- 包签名必须绑定真实发布者信任记录；自己导入的未签名包显示具体来源与未验证状态，不能因 `publisher=official` 自称可信。
- 对每个分段核对实际字节、ESP镜像头、芯片兼容性、分区表和对齐要求；签名通过仍须做这些检查。
- 地址、范围、文件大小与布局声明冲突时拒绝；下载响应头或包内新公钥不能替换现有信任锚。
- 写入影响按工具实际擦除扇区边界计算，不能只显示文件字节范围；邻接 NVS/字体/其他区域被擦除也必须纳入计划。填充的 `0xff` 字节并不意味着跳过该区域。
- 恢复包须在开始写入前本地可用并校验通过；恢复包本身的板级/安全状态也要匹配。
- 上游原始发布文件只读缓存，归一化清单或导出 bundle 时保留发布文件所在提交/Release、原文件 hash 和分段来源。发布文件所在 Git 提交与编译源码提交分别记录，不把两者自动视作相同。不把未知 `.bin` 按猜测地址写入。

## NVS 与字体

官方当前 `font` 分区虽然标记为 `data/spiffs`，应用实际 mmap 裸 TTF。不能按 SPIFFS 文件系统自动格式化或迁移。官方完整合并镜像覆盖 NVS 区域；“保留设置”必须是布局、版本和实际写入范围共同证明的结果。

上游 20260814 / 20260815 合并镜像的 factory 为 1 MiB 且没有 font 条目，20260821 / 20260910 为 2 MiB factory + 4 MiB font。不能为整个官方仓库指定唯一通用布局；根目录历史 app 产物也不能按完整镜像从 `0x0` 写入。详见 [内置目录记录](../src/typix_copilot/catalog.json)。

应用更新允许保留 NVS 或字体的前提是显式匹配当前布局、数据结构及固件要求；否则显示不兼容，要求选择已审核迁移/恢复流程。自研与第三方固件的 NVS 命名空间不能默认互通。

备份文件和用户配置从不进入公开固件库。公开库可存清单、签名、许可证、截图和无用户数据的构建产物。

## 当前官方布局的参考数值

| 区域 | 偏移 | 大小 |
| --- | --- | --- |
| NVS | `0x9000` | `0x6000` |
| PHY 初始化 | `0xf000` | `0x1000` |
| factory 应用 | `0x10000` | `0x200000` |
| font（裸TTF） | `0x210000` | `0x400000` |

这些数值来自固定上游版本，用于建立首个审核配置；运行时不能仅按 CM4/CM5 型号硬编码写入。参考：[官方分区表](https://github.com/TypixNode/TypixDeck-esp32s3-firmware/blob/fde9dac3b687a92fa2a6a049b5cd953dcb367b23/partitions.csv)、[esptool 写入与安全限制](https://docs.espressif.com/projects/esptool/en/latest/esp32s3/esptool/basic-commands.html)。
